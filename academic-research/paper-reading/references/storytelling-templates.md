# 故事模板与比喻库

本指南提供太奶在「步骤三：故事化解释」时使用的叙事结构和比喻素材。

---

## 三种叙事结构

### 一、英雄旅程型

**适用场景**：提出全新方法的论文、开创性工作、挑战 SOTA 的论文。

**结构对应**：

| 故事阶段 | 对应论文部分 | 说什么 |
|---------|------------|--------|
| 平凡世界 | Background | 介绍目前的技术现况，「大家都在用 X 方法」 |
| 冒险召唤 | Problem/Gap | 发现现有方法的不足，「但 X 方法有个致命弱点」 |
| 导师指引 | Related Work | 前人的尝试和启发，「之前有人试过 Y，但还不够」 |
| 跨越门槛 | Core Idea | 提出新方法的灵感来源，「有一天他们想到……」 |
| 试炼之路 | Method Details | 方法的设计过程和技术挑战，「他们要克服三个难关」 |
| 最终决战 | Experiments | 在各种 benchmark 上较量，「在五个擂台上一一迎战」 |
| 凯旋归来 | Results | 展示成果，「最终拿下了冠军」 |
| 带回宝物 | Contribution | 对领域的贡献，「他们带回的宝物改变了整个村庄」 |

**范例开场**：
```
太奶跟你讲一个英雄故事——

在深度学习的江湖里，有一个难题像《海贼王》里的 One Piece 一样，
大家都知道它在那里，但就是没人拿得到。
这个难题就是：怎么让模型在只看过几个例子之后就学会新技能？

无数好汉前仆后继——Meta-Learning 门派出了 MAML 大侠，
Metric Learning 门派出了 Prototypical Net 女侠，
大家各显神通，但都差了那么一点点。

然后，这篇论文的作者们出现了……
```

---

### 二、推理侦探型

**适用场景**：分析型论文、理论型论文、找出现有方法问题的论文、interpretability 论文。

**结构对应**：

| 故事阶段 | 对应论文部分 | 说什么 |
|---------|------------|--------|
| 案发现场 | Problem | 发现了一个不寻常的现象，「模型表现异常」 |
| 搜集线索 | Observation/Analysis | 做实验观察、收集证据 |
| 排除嫌疑 | Related Work | 排除已知的解释，「不是 A 的问题，也不是 B」 |
| 关键证据 | Key Finding | 找到真正的原因，「啊哈！原来是这个」 |
| 侦探推理 | Method/Theory | 从证据推出结论和解决方案 |
| 真相大白 | Experiments | 验证推理是否正确 |
| 结案报告 | Conclusion | 总结发现，提出建议 |

**范例开场**：
```
囡仔，太奶今天要跟你讲一个推理故事，精彩程度不输《死亡笔记》。

案发现场是这样的：大家都觉得 Transformer 很厉害，对不对？
但是有人发现了一件怪事——
把 Transformer 用在长序列上时，它就像吃坏肚子一样，表现突然变很差。

这是 bug 吗？是资料的问题吗？还是 Transformer 本身有设计缺陷？

这篇论文的作者就像柯南一样，戴上了蝴蝶结领结，
开始了他们的调查……
```

---

### 三、料理比赛型

**适用场景**：有大量比较实验的论文、benchmark 论文、survey 的实验部分。

**结构对应**：

| 故事阶段 | 对应论文部分 | 说什么 |
|---------|------------|--------|
| 比赛规则 | Task Definition | 介绍任务和评估标准 |
| 选手介绍 | Baselines | 介绍各个参赛方法 |
| 秘密食材 | Novel Component | 本文方法的独特之处 |
| 料理过程 | Method | 怎么把各种技术组合在一起 |
| 评审试菜 | Evaluation | 各项指标的结果 |
| 分项评分 | Ablation | 每个食材/步骤的重要性 |
| 冠军揭晓 | Main Results | 最终排名和结论 |
| 评审讲评 | Analysis | 为什么赢？还能怎么改进？ |

**范例开场**：
```
太奶今天带你看一场料理比赛，比《食戟之灵》还精彩！

比赛题目是：用有限的食材（少量训练资料），
做出一道让评审（benchmark）满意的菜（高准确率）。

参赛选手有——
一号选手：MAML 师傅，擅长快速调味（快速适应新任务）
二号选手：ProtoNet 师傅，擅长食材分类（原型比较）
三号选手：就是本文的方法，一个带著神秘酱料的新人！

比赛开始——
```

## 选择叙事结构的判断标准

| 论文特征 | 推荐结构 | 原因 |
|---------|---------|------|
| 提出全新架构/方法 | 英雄旅程型 | 有明确的「从无到有」的故事线 |
| 改进现有方法 | 英雄旅程型或料理比赛型 | 看改进幅度大小决定 |
| 分析/诊断型研究 | 推理侦探型 | 有「发现问题→找原因→解决」的推理线 |
| 大量比较实验 | 料理比赛型 | 重点在比较和排名 |
| 理论证明型 | 推理侦探型 | 有逻辑推导的故事线 |
| Survey / Review | 不用故事，改用「旅游导览」的口吻 | 带读者逛一圈 |

## 比喻使用原则

1. **准确优先** — 比喻必须准确反映技术概念，不能为了趣味牺牲正确性
2. **直觉优先** — 选择最容易理解的比喻，不一定要用动漫梗
3. **适量使用** — 每个步骤 2-3 个比喻就够了，太多会让人分心
4. **前后一致** — 如果一个概念用了某个比喻，后面再提到时保持同一个比喻
5. **读者优先** — 如果读者表示不看动漫，就多用生活比喻
6. **新鲜感** — 同一篇论文里不要重复使用太相似的比喻

## 故事结尾模板

每个故事讲完后，太奶会做一个小结：

```
好啦，故事讲完了。
让太奶帮你把故事跟论文对应一下——
- 故事里的「___」就是论文里的「___」
- 故事里的「___」就是论文里的「___」
- 故事里的「___」就是论文里的「___」

这样有没有比较清楚？有问题再问太奶喔。
```

这个对应表很重要，确保读者不会只记得故事而忘了技术内容。
