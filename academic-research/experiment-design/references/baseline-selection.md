# Baseline 选择指南

## 概述

Baseline（基线方法）的选择直接影响实验结果的可信度与说服力。本文件提供系统化的 Baseline 选择策略，确保实验比较的公平性与完整性。

---

## 一、为什么 Baseline 选择很重要

- **可信度**：与强 Baseline 比较才能证明方法的价值
- **定位**：Baseline 帮助读者理解你的方法在研究谱系中的位置
- **公平性**：不当的 Baseline 选择是审稿人最常提出的批评之一
- **完整性**：多样的 Baseline 展示方法在不同维度上的优劣

---

## 二、必选 Baseline 类型

### 2.1 经典方法（Classic Methods）

**定义**：该领域历史上具有里程碑意义的方法。

**选择标准**：

- 被广泛引用且普遍认可
- 通常有成熟稳定的实现
- 代表该领域的「传统」解决方案

**范例**：

| 领域 | 经典方法范例 |
|------|-------------|
| 文本分类 | TF-IDF + SVM、TextCNN |
| 序列标注 | BiLSTM-CRF |
| 机器翻译 | Transformer (Vaswani et al., 2017) |
| 影像分类 | ResNet |
| 物件侦测 | Faster R-CNN |

**目的**：展示新方法相对于经典方法的进步幅度，提供历史脉络。

### 2.2 当前 SOTA（State-of-the-Art）

**定义**：在你的目标任务与资料集上，目前表现最佳的方法。

**选择标准**：

- 在相同资料集上有公开的结果
- 发表时间尽可能接近你的投稿时间
- 最好有开源的程式码可供使用

**注意事项**：

- SOTA 会随时间变化，需在投稿前确认最新进展
- 若 SOTA 方法使用了额外资料或更大的预训练模型，需特别说明
- 建议选择 2-3 个近期的 SOTA 方法

**目的**：展示新方法是否真正推进了该领域的技术前沿。

### 2.3 简单 Baseline（Simple Baselines）

**定义**：不使用复杂模型的简单方法，用以确立效能下界。

**常见类型**：

| 类型 | 说明 | 范例 |
|------|------|------|
| 随机基线 | 随机预测 | 随机分类器 |
| 多数类别 | 总是预测最常见的类别 | Majority Class |
| 简单统计 | 基于简单统计特征 | TF-IDF + 逻辑回归 |
| 直接迁移 | 不做任何调整的预训练模型 | Zero-shot GPT |
| 人类表现 | 人工标注的一致性 | Human Agreement |

**目的**：

- 确认任务本身具有一定的复杂度（避免简单方法就能解决的情况）
- 为后续的改进提供参照基准
- 有时简单 Baseline 的表现出乎意料地好，这本身就是重要发现

## 三、公平比较原则

### 3.1 资料一致性

所有方法必须使用：

- **相同的训练集**：相同的资料切分、相同的版本
- **相同的验证集**：用于超参数调整
- **相同的测试集**：用于最终评估
- **相同的前处理**：除非前处理本身是研究贡献

### 3.2 评估一致性

- 使用相同的评估指标与计算方式
- 使用相同的评估脚本（避免实现差异）
- 在相同的硬体环境下测量效率指标

### 3.3 资源一致性

- 模型参数量应在同一量级（或明确报告差异）
- 训练计算量应可比较
- 若使用预训练模型，应使用相同版本

### 3.4 调参一致性

- 为 Baseline 方法进行合理的超参数调整
- 不能只对自己的方法调参而使用 Baseline 的预设参数
- 记录所有方法的调参范围与最佳超参数

### 3.5 Baseline 结果的来源

优先顺序如下：

1. **使用原作者的开源程式码重新跑**：最可靠
2. **引用原论文的数字**：需确保实验条件一致
3. **从排行榜取得数字**：需确认评估条件相同
4. **自行重新实现**：需验证重现结果与原论文接近

## 四、Baseline 选择的策略

### 4.1 文献调研策略

1. 阅读目标任务最近 2-3 年的代表性论文
2. 整理这些论文中使用的 Baseline 列表
3. 找出被最多论文使用的 Baseline（高频 Baseline）
4. 加入最新发表的方法

### 4.2 Baseline 数量建议

| 论文类型 | 建议数量 |
|----------|----------|
| 顶会长文 | 5-10 个 |
| 顶会短文 | 3-5 个 |
| Workshop | 2-4 个 |

### 4.3 Baseline 分类展示

在实验结果表中，建议将 Baseline 分类展示：

```
表1：XX 资料集上的实验结果

方法                      | F1    | Acc
--------------------------|-------|------
--- 简单基线 ---
Majority Class            | 32.1  | 45.2
TF-IDF + LR              | 65.3  | 68.7
--- 经典方法 ---
TextCNN (Kim, 2014)       | 78.2  | 80.1
BiLSTM (Hochreiter, 1997) | 79.5  | 81.3
--- 近期 SOTA ---
BERT (Devlin, 2019)       | 88.3  | 89.7
RoBERTa (Liu, 2019)       | 89.1  | 90.2
--- 我们的方法 ---
Ours                      | 90.5  | 91.8
```

## 五、常见错误与避免方式

### 5.1 Cherry-Picking（选择性比较）

**错误**：只与较弱的方法比较，避开强力 Baseline。

**避免方式**：

- 包含该领域公认的 SOTA 方法
- 使用其他近期论文中的 Baseline 列表作为参考
- 若方法在某些 Baseline 上没有优势，坦诚报告并分析原因

### 5.2 不公平的比较条件

**错误**：自己的方法使用了更大的模型、更多的资料或更强的预训练，但未说明。

**避免方式**：

- 明确报告所有方法的参数量
- 标明各方法使用的预训练模型
- 在相同参数量下进行对比实验

### 5.3 过时的 Baseline

**错误**：所有 Baseline 都是 3 年以上的旧方法。

**避免方式**：

- 至少包含 1-2 个近一年内发表的方法
- 投稿前检查是否有新的 SOTA 出现
- 关注 arXiv 上的最新预印本

### 5.4 Baseline 未充分调参

**错误**：Baseline 使用预设超参数，自己的方法经过精心调参。

**避免方式**：

- 为每个 Baseline 进行合理的超参数搜索
- 使用 Baseline 原论文推荐的超参数范围
- 报告 Baseline 的最佳超参数

### 5.5 忽略简单 Baseline

**错误**：只与复杂方法比较，忽略简单方法可能就够好的事实。

**避免方式**：

- 始终包含至少一个简单 Baseline
- 若简单方法表现不错，诚实报告并讨论

### 5.6 评估指标不一致

**错误**：不同方法使用不同的评估脚本或评估设定。

**避免方式**：

- 所有方法使用同一份评估程式码
- 确认 tokenization、后处理等步骤一致
- 使用官方评估脚本（若有的话）

---

## 六、Baseline 选择检查清单

- [ ] 包含至少一个简单 Baseline
- [ ] 包含该领域的经典方法
- [ ] 包含最近 1-2 年的 SOTA 方法
- [ ] 所有 Baseline 使用相同的资料切分
- [ ] 所有 Baseline 使用相同的评估指标与脚本
- [ ] 所有 Baseline 都经过合理的超参数调整
- [ ] Baseline 的来源已记录（原始程式码 / 重新实现 / 引用数字）
- [ ] 参数量与计算量的差异已明确报告
- [ ] Baseline 数量足够（符合目标会议的惯例）
