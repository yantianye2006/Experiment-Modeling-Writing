# 实验设计技能

## 概述

本技能提供一套结构化的实验设计流程，适用于机器学习、自然语言处理、电脑视觉等领域的学术研究。目标是协助研究者从模糊的研究想法出发，产出一份严谨、可重现、且具说服力的实验计划。

## 核心设计理念

好的实验设计应具备以下特质：

- **可证伪性**：实验结果必须能够支持或否定研究假设
- **公平性**：所有比较对象在相同条件下评估
- **可重现性**：他人能够依据描述完整重现实验
- **充分性**：实验覆盖足够的面向以支撑论文结论

---

## 实验设计 Pipeline

完整的实验设计遵循以下六步流程：

```
假设 → 变数 → 指标 → Baseline → Ablation → 计算预算
```

每一步的产出都是下一步的输入，形成严谨的推导链。

---

## 步骤一：研究假设明确化

### 目的

将模糊的研究动机转化为可验证的具体假设。

### 方法

1. **辨识研究问题**：你想回答什么问题？
2. **提出核心假设**：对问题的预期答案是什么？
3. **明确化假设**：假设必须具备可测量性与可证伪性
4. **分解子假设**：将复杂假设拆解为可逐一验证的子假设

### 假设的品质标准

| 标准 | 说明 |
|------|------|
| 具体性 | 明确指出预期的效果方向与幅度 |
| 可测量性 | 可以用量化指标来验证 |
| 可证伪性 | 存在可能否定假设的实验结果 |
| 相关性 | 与研究问题直接相关 |

### 范例

- 不佳：「我们的方法比较好」
- 良好：「在 SQuAD 2.0 资料集上，加入跨注意力机制后，F1 分数相较于纯自注意力基线提升至少 2 个百分点」

详见：[实验规划参考](references/experiment-planning.md)

## 步骤二：变数定义

### 自变数（Independent Variables）

研究者主动操控的变数，即实验中「改变的东西」。

- 模型架构的变体
- 训练策略的差异
- 资料处理方式的不同

### 依变数（Dependent Variables）

用来衡量实验结果的变数，即「被测量的东西」。

- 模型效能指标（准确率、F1、BLEU 等）
- 效率指标（推论时间、记忆体用量）
- 品质指标（人工评估分数）

### 控制变数（Control Variables）

实验中保持不变的变数，确保比较的公平性。

- 随机种子
- 训练资料集与切分方式
- 超参数（非研究对象的部分）
- 硬体环境
- 预训练模型版本

### 变数控制原则

1. **单一变数原则**：每次实验仅改变一个自变数
2. **完整记录原则**：所有变数的值都必须记录
3. **合理范围原则**：自变数的取值范围应有理论依据

详见：[实验规划参考](references/experiment-planning.md)

## 步骤三：评估指标选择

### 选择原则

1. **领域惯例**：优先选择该领域公认的标准指标
2. **多面向覆盖**：同时报告效能、效率、稳健性指标
3. **统计显著性**：报告多次实验的平均值与标准差
4. **合理性**：指标能真正反映研究假设所关注的面向

### 常见指标类别

| 类别 | 指标范例 |
|------|----------|
| 分类任务 | Accuracy、Precision、Recall、F1-score、AUC-ROC |
| 生成任务 | BLEU、ROUGE、METEOR、BERTScore、人工评估 |
| 资讯撷取 | MAP、MRR、NDCG、Recall@K |
| 效率指标 | FLOPs、参数量、推论延迟、记忆体占用 |
| 稳健性 | 跨资料集表现、对抗样本准确率 |

### 统计检验

- 报告多次随机种子实验的平均值与标准差
- 必要时进行统计显著性检验（如 paired t-test、bootstrap test）
- 标注统计显著性水准（p < 0.05, p < 0.01）

## 步骤四：Baseline 选择与设定

### 必选 Baseline 类型

1. **经典方法**：该领域历史上重要的方法
2. **当前 SOTA**：最新的最佳表现方法
3. **简单 Baseline**：简单但合理的基准方法（如随机、多数类别、TF-IDF）

### 公平比较原则

- 使用相同的资料切分
- 使用相同的评估协定
- 尽可能使用原作者的程式码与超参数
- 若需重新实现，需验证重现结果与原论文一致

### 常见错误

- 仅与弱基线比较
- 未使用最新 SOTA 作为基线
- 基线的超参数未经调校
- 比较条件不一致（如不同的预训练模型）

详见：[Baseline 选择指南](references/baseline-selection.md)

## 步骤五：Ablation Study 设计

Ablation Study 是验证方法中各组件贡献的关键实验。本技能定义四种 Ablation 模式：

### 模式一：完整消融（Component Ablation）

逐一移除或替换方法中的各个组件，观察效能变化。

- 每次仅移除一个组件
- 记录移除后的效能变化
- 借此判断每个组件的贡献度

### 模式二：超参敏感度分析（Hyperparameter Sensitivity）

探讨关键超参数对效能的影响。

- 选择 2-4 个最重要的超参数
- 在合理范围内变化超参数值
- 绘制超参数-效能曲线图

### 模式三：跨资料集迁移（Cross-Dataset Transfer）

验证方法的泛化能力。

- 在多个不同资料集上测试
- 包含不同规模、不同领域的资料集
- 分析方法在何种条件下效果最佳或最差

### 模式四：定性分析（Qualitative Analysis）

透过可视化与案例分析深入理解模型行为。

- 注意力权重视觉化
- 成功与失败案例分析
- 特征空间视觉化（如 t-SNE）
- 错误类型分类与统计

详见：[Ablation 设计指南](references/ablation-design.md)

## 步骤六：计算资源预估

### 预估项目

1. **单次实验成本**
   - GPU 时数
   - 记忆体需求
   - 储存空间需求

2. **实验总量计算**

   ```
   总 GPU 时数 = 单次时数 × 模型变体数 × 资料集数 × 随机种子数 × 超参组合数
   ```

3. **安全系数**
   - 建议预留 1.5-2 倍的预估资源
   - 考虑除错、预实验、追加实验的需求

### 资源最佳化策略

- 先以小规模资料集进行预实验
- 使用早停（early stopping）节省训练时间
- 善用混合精度训练（mixed precision）
- 合理安排实验优先顺序

## 可重现性要求

实验计划必须包含完整的可重现性资讯，确保他人能够精确重现结果。

### 必要揭露项目

1. **硬体环境**
   - GPU 型号与数量
   - CPU 规格
   - 记忆体大小

2. **软体环境**
   - 程式语言版本
   - 深度学习框架版本
   - 关键套件版本

3. **随机性控制**
   - 随机种子设定
   - 确定性演算法设定
   - 多次实验的种子列表

4. **训练协定**
   - 完整的超参数列表
   - 优化器设定
   - 学习率排程
   - 资料增强策略
   - 早停准则

5. **资料处理**
   - 资料集版本与来源
   - 前处理步骤
   - 资料切分方式

6. **评估协定**
   - 评估指标的精确定义
   - 评估频率
   - 模型选择准则

详见：[可重现性清单](references/reproducibility-checklist.md)

## 输出：结构化实验计划文件

本技能的最终产出为一份结构化的实验计划文件，包含以下章节：

1. 研究假设与子假设
2. 变数定义表
3. 评估指标与统计方法
4. Baseline 列表与设定
5. Ablation Study 设计矩阵
6. 计算资源预估与时程规划
7. 可重现性资讯

## 使用流程

### 输入

- 研究主题或论文草稿
- 提出的方法描述
- 可用的计算资源

### 处理

1. 引导使用者明确化研究假设
2. 协助定义自变数、依变数、控制变数
3. 根据任务类型建议评估指标
4. 根据研究领域建议 Baseline
5. 设计 Ablation Study 方案
6. 预估计算资源需求

### 输出

- 完整的实验计划文件（依照模板格式）
- 实验优先顺序建议
- 潜在风险与应对方案

## 品质检查清单

在完成实验计划后，请确认以下项目：

- [ ] 每个研究假设都有对应的实验来验证
- [ ] 所有自变数的取值范围已明确定义
- [ ] 控制变数已完整列出
- [ ] 评估指标涵盖多个面向
- [ ] Baseline 包含经典方法、SOTA、简单基线
- [ ] Ablation Study 覆盖所有提出的组件
- [ ] 计算资源预估合理且包含安全系数
- [ ] 可重现性资讯完整
- [ ] 统计检验方法已确定
